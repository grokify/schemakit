    Release Notes: schemakit v0.6.0¶

    Release Date: 2026-10-07

    Overview¶

    This release lets schemakit generate document the schemas it produces: Go doc comments become property and type descriptions, and new flags set the schema's $id, title, and description. It also fixes the release pipeline, so prebuilt binaries are attached to a release again for the first time since v0.3.0, and reorganizes the documentation tree.

    Highlights¶

    • Descriptions from Go comments: generate --comments keeps the Go source as the single place a contract is documented
    • Schema metadata flags: --id, --title, and --description set the schema's top-level keywords
    • Release binaries are back: the GoReleaser configuration still used the project's former name, so v0.4.0 and v0.5.0 published no binaries
    • Docs reorganized: user guides live under docs/guides/ and the changelog under docs/releases/

    New Features¶

    Descriptions from Go Comments (--comments)¶

    With --comments, Go doc comments on types and fields become description fields in the generated schema:

    // Config configures the service.
type Config struct {
    // Host is the database host name.
    Host string `json:"host"`
}

    schemakit generate --comments -o schema.json github.com/myorg/myproject/types Config
    • A type's comment contributes its first sentence; a field's comment contributes its full text.
    • On a field, a jsonschema:"description=…" tag takes precedence over the comment.
    • Comments are read from the target package's directory and below. Types from other packages are reflected but get no descriptions.
    • Every .go file under that directory is parsed, so an invalid file (for example under testdata) makes generation fail.

    Schema Metadata (--id, --title, --description)¶

    Set the top-level keywords directly, for example when the schema is published at a stable URL:

    schemakit generate --comments \
  --id https://example.com/schemas/config.schema.json \
  --title "Config" --description "Application configuration." \
  -o schema.json github.com/myorg/myproject/types Config

    Values are quoted before they are placed in the generated program, so quotes, newlines, and backslashes are safe. Without --id, the default $id is still derived from the package path and type name.

    Development Build Versions¶

    schemakit version now reports the module version, commit, and build time from Go build info for go build and go install builds, instead of a bare dev.

    Fixes¶

    Release Binaries¶

    The GoReleaser configuration was not updated when the project was renamed from schemalint to schemakit. It still pointed at ./cmd/schemalint, which no longer exists, so the release workflow failed with couldn't find main file for v0.4.0 and v0.5.0 and attached no binaries to those releases. The configuration now uses the schemakit project, binary, and build path. Archives are named schemakit_<version>_<os>_<arch> and contain the binary, the README, the license, and the changelog.

    Upgrade Notes¶

    • Documentation URLs changed. User guides moved under docs/guides/, so /commands/generate/ is now /guides/commands/generate/, /installation/ is /guides/installation/, and /reference/profiles/ is /guides/reference/profiles/. Update any bookmarks or links.
    • The changelog moved. CHANGELOG.json and CHANGELOG.md are now in docs/releases/ instead of the repository root, so the changelog is published with the documentation site. It is less prominent on the repository front page.
    • Homebrew instructions removed. brew install grokify/tap/schemakit never worked: the tap only has a schemalint formula and releases publish none. Use go install or a release archive.

    Installation¶

    Go Install¶

    go install github.com/grokify/schemakit/cmd/schemakit@latest

    Release Binaries¶

    Download the archive for your platform from the GitHub release, extract it, and put schemakit on your PATH.

    Commands¶

    Command Description
    schemakit lint Check schemas for static type compatibility (profiles: default, scale, navigable)
    schemakit generate Generate JSON Schema from Go struct types (--check for drift guard, --comments for descriptions)
    schemakit doc Generate Markdown documentation from Go types
    schemakit version Print version information
